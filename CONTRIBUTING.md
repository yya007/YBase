# Contributing

Thanks for helping. The full guide is [`docs/contributing.md`](docs/contributing.md): development commands, conventions, the gate every change must pass, and how to add a profile, a hook, a check or a skill.

Before you open an issue or a pull request, check that it holds nothing private: no repo names of your own, no local paths, no content from your knowledge base, no `.env` values. YBase is a public framework and everything in it must be true and harmless for a stranger.
