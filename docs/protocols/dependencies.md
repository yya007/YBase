# Dependencies: lockfiles and reproducible environments in managed repos

Open this before adding, removing or upgrading a dependency in a managed repo. YBase's own tools are the exception: they run on bash 3.2 and the Python standard library, so they have no runtime dependencies at all.

## Lockfiles

- Commit lockfiles (`uv.lock`, `package-lock.json`, `pnpm-lock.yaml`, `go.sum`, `Cargo.lock` and the like). They are generated by the tool; never edit one by hand.
- Install and run tools through the repo's lockfile-native package manager, for example `uv` for Python and `pnpm` or `npm` for Node, so the pinned environment is the one that runs. Do not call a globally installed interpreter instead.

## Runtime versions

Pin each language's runtime version in one place per repo: `requires-python` in `pyproject.toml`, `engines` in `package.json`, `.tool-versions` for asdf, the `go` directive in `go.mod`.

## Adding one

- State its purpose in the PR body.
- Check its licence against the repo's allowed set. Without one, the default is a permissive open-source licence: MIT, BSD or Apache-2.0.
- Bump the lockfile in the same commit.
- A large dependency or framework change needs the user's agreement first ([`rules.md`](../rules.md), Safety).

## Security patches

Apply vulnerability and security patches promptly; they do not need to be asked about first. Verify them with the test suite like any other change.

## Removing one

Search for remaining imports and uses before removing a dependency. A leftover import can still pass lint when the package is vendored elsewhere, and then fails only at run time.
